# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope (UI only):** one page that shows live connection status, a broadcast send form, and a newest-first notification list with a toast on every arrival. Covers CONN-02, CONN-03 (visible part), BCST-01, BCST-02, BCST-03. Not in this phase: username/login, user and group send, debug panel (Phase 2), task button (Phase 3), unread badge, manual reconnect button (Phase 4). Do not build placeholders for them.

**Provenance of decisions:** No CONTEXT.md, no phase RESEARCH.md, and no user answers exist. Every value below comes from STACK.md, ARCHITECTURE.md, FEATURES.md, REQUIREMENTS.md and ROADMAP.md, or is an **[ASSUMPTION]** (a recommended default the user has not confirmed). See the Assumptions section at the end; override there and the rest of the contract follows.

## Spacing Scale

Declared values (all multiples of 4). Expose as `--space-xs` through `--space-3xl`.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Gap between kind badge and timestamp; gap between status dot and label |
| sm | 8px | Badge padding (vertical 4px / horizontal 8px), gap between input and button, gap between list rows |
| md | 16px | Card padding, list row padding, gap between label and input |
| lg | 24px | Page side padding, gap between header, form card and list |
| xl | 32px | Page top padding |
| 2xl | 48px | Bottom page padding |
| 3xl | 64px | Not used in Phase 1 (reserved) |

Exceptions:
- Form controls (text input and Send button) have a **minimum height of 44px** so they are easy to hit and read on a projector.
- Status dot is 12px by 12px (a multiple of 4).

## Typography

Exactly 4 sizes and 2 weights (400 regular, 600 semibold). Expose as `--font-size-*`.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Body | 16px | 400 | 1.5 | Notification message text, input text, hint text under the status, empty-state body |
| Label | 14px | 600 | 1.5 | Form label, kind badge text, status pill text, timestamp (400 weight for timestamp) |
| Heading | 20px | 600 | 1.2 | Section headings "Send a broadcast" and "Notifications", empty-state heading |
| Display | 28px | 600 | 1.2 | Page title only |

Notes:
- Timestamp uses Label size at weight 400 and muted color. This reuses the 14px size and does not add a new weight.
- Muted/hint text in body size uses the muted color, not a smaller size.
- Never add a fifth size or a third weight. Badges, timestamps and toast text must reuse the four above (sonner's own toast typography is left at its defaults).

## Color

Light theme only (**[ASSUMPTION]** no dark mode; FEATURES.md rates polished theming as no teaching value). Expose as CSS custom properties.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, notification list rows |
| Secondary (30%) | `#F1F5F9` | Send form card, header status strip background, empty-state panel, kind-less neutral surfaces |
| Accent (10%) | `#2563EB` | See reserved list below |
| Destructive | `#B91C1C` | No destructive actions in Phase 1. Reserved; used only as the Disconnected status color and inline send-error text (semantic, never a button fill) |
| Text | `#0F172A` | Headings, body, message text (contrast 17:1 on white) |
| Muted text | `#475569` | Hints, timestamps, placeholder-adjacent copy (7.6:1 on white, 6.6:1 on `#F1F5F9`) |
| Border (control) | `#64748B` | Text input border (4.8:1, meets the 3:1 non-text rule) |
| Border (decorative) | `#CBD5E1` | Card and list-row dividers |

Accent reserved for (and nothing else):
1. Background of the **Send broadcast** primary button (white text, 5.2:1)
2. The 2px focus ring (`outline: 2px solid #2563EB; outline-offset: 2px`) on every focusable element
3. The newly arrived list row highlight (tint `#DBEAFE` fading to transparent)
4. The **Broadcast** kind badge (text `#1D4ED8` on `#DBEAFE`)

### Status colors (semantic, text label always present, never color alone)

| Status | Dot and text color | Dot behavior |
|--------|--------------------|--------------|
| Connecting | `#92400E` (amber) | Pulses (opacity 1 to 0.4, 1s loop) |
| Connected | `#15803D` (green) | Solid |
| Reconnecting | `#92400E` (amber) | Pulses |
| Disconnected | `#B91C1C` (red) | Solid |

`@media (prefers-reduced-motion: reduce)`: no pulse, no row highlight fade; show the end state immediately.

### Kind labels (BCST-03)

Define all four now so later phases do not touch the badge component. Badge is a rounded (radius 8px) pill: Label size, weight 600, padding 4px 8px. Text is the kind name, so color is never the only signal.

| `kind` value (server payload) | Badge text | Text color | Background |
|-------------------------------|-----------|------------|-----------|
| `broadcast` | Broadcast | `#1D4ED8` | `#DBEAFE` |
| `user` | User | `#6D28D9` | `#EDE9FE` |
| `group` | Group | `#0F766E` | `#CCFBF1` |
| `task` | Task | `#92400E` | `#FEF3C7` |
| any other value | the raw `kind` string, or "Notification" if missing | `#0F172A` | `#F1F5F9` |

Only `broadcast` can occur in Phase 1; render the other three correctly anyway.

## Layout and Interaction Contract

### Page structure (single column, top to bottom)

1. **Header row.** Page title (Display) on the left, status pill on the right. Wraps to two lines below 480px. A hint line (Body, muted) sits directly under the header row. It is empty unless a status needs one, but always reserves one line of height (24px) so the page does not shift when a hint appears or clears.
2. **Send card.** Secondary surface, radius 8px, padding 16px. Heading "Send a broadcast" (Heading). Below it a `<form>` with a visible `<label>` "Message", a text input, and the Send button. Input and button sit in one row with 8px gap; below 480px the button goes full width under the input.
3. **Notifications.** Heading "Notifications" (Heading), then either the empty state or the list.

Container: `max-width: 720px`, centered, side padding 24px, top padding 32px, bottom padding 48px. Body background `#FFFFFF`.

### Connection status pill (CONN-02, CONN-03)

- Element: `<div role="status" aria-live="polite">` containing the 12px dot and the status text (Label). It is a pill with Secondary background, radius 8px, padding 4px 16px.
- It shows exactly one of four states, mapped one-to-one from the connection lifecycle: `connecting` on mount and while the initial-start retry loop runs, `connected` after `start()` resolves or `onreconnected`, `reconnecting` on `onreconnecting`, `disconnected` on `onclose`.
- **Initial-start failure (server not up yet):** keep showing **Connecting** (not Disconnected) and show the hint line "Can't reach the server yet. Retrying every 2 seconds." The loop retries every 2 seconds, forever, until `start()` succeeds, then the pill moves to Connected and the hint clears with no page refresh. The 2 second interval is an **[ASSUMPTION]**.
- **Disconnected** (automatic reconnect gave up): hint line "Connection lost. Reload the page to reconnect." Phase 4 replaces this hint with a Reconnect button; do not build the button now.
- **Reconnecting** hint: "Connection dropped. Trying to reconnect." Clears on Connected.
- The StrictMode double-mount must not produce two pills, two connections, or a flash of "Disconnected": a start that was cancelled by effect cleanup must not set status (the `disposed` guard from ARCHITECTURE.md Pattern 4).

### Send form (BCST-01)

- Label "Message" is visible and associated with the input via `htmlFor`/`id` (no placeholder-only labelling). Placeholder: "Say something to every open tab".
- Input: `type="text"`, `maxLength={280}`, `autoComplete="off"`, height 44px, 1px `#64748B` border, radius 8px, padding 0 16px.
- Submit by clicking the button or pressing Enter (native `<form onSubmit>`; the button is `type="submit"`).
- Button label: **Send broadcast**. Accent fill, white text, Label size, radius 8px, min height 44px, padding 0 24px.
- **Disabled when** status is not Connected, or the trimmed message is empty, or a send is in flight. Disabled style: Secondary-dark fill `#CBD5E1`, text `#475569`, `cursor: not-allowed`. Use the `disabled` attribute (keeps it out of the tab order and announces it).
- When status is not Connected, the input stays editable so a presenter can type ahead; only the button is disabled. Pressing Enter while disabled does nothing.
- On submit: trim the message, `connection.invoke("SendBroadcast", message)`. While awaiting, the button shows "Sending…" and is disabled.
- On success: clear the input, return focus to the input. Do **not** add the entry locally; it arrives through the same `ReceiveNotification` handler as everyone else (sender sees exactly one toast and one list row; Decisions Carried From Research in REQUIREMENTS.md).
- On failure: keep the typed text, show inline error text under the form (Body, `#B91C1C`, `role="alert"`): "Message not sent. The connection dropped. Wait for Connected, then try again." The error clears on the next input change or successful send.

### Notification list (BCST-02)

- Semantic `<ol>`, **newest first** (prepend on receive), list style none. Capped at the **50** most recent entries in client state; older entries drop off the end (**[ASSUMPTION]**, from FEATURES.md "cap list at ~50"). The list grows the page; the page scrolls, the list does not get its own scroll box.
- Each `<li>`: white background, 1px `#CBD5E1` bottom divider, padding 16px. Content in this order: first line is the kind badge then 4px gap then the timestamp (Label size, weight 400, muted); second line is the message (Body, text color, `overflow-wrap: anywhere`, preserves nothing but plain text). Timestamp is the server `sentAt` rendered with `toLocaleTimeString([], { hour: "2-digit", minute: "2-digit", second: "2-digit" })` inside a `<time dateTime={sentAt}>`. Seconds are shown so the audience can see delivery latency.
- Messages render as **text only**. Never use `dangerouslySetInnerHTML`.
- A newly arrived row plays the accent highlight once (`#DBEAFE` to transparent over 1s). No slide or scale animation.
- The list is **not** an `aria-live` region. The toast's live region announces arrivals; making the list live too would announce each message twice.
- React `key` is the notification `id`. A notification whose `id` is already in the list is ignored (guards against double delivery, including a StrictMode double handler).

### Toast (BCST-02)

- One `<Toaster position="top-right" visibleToasts={3} closeButton />`. No `richColors` (keeps the palette above in control).
- Per notification: `toast(kindLabel, { id: notification.id, description: notification.message, duration: 5000 })`. Title is the kind label text from the table above ("Broadcast"); description is the message. Passing the notification `id` as the toast id makes a duplicate call replace rather than stack, so even a stray double handler cannot show two toasts.
- Toast is fired from the single `connection.on("ReceiveNotification", ...)` handler, never from render and never from the send form. The sender's own tab shows it too.
- Do not add a second live region around the toaster. Sonner provides its own.

### Keyboard and accessibility

- Tab order: input, Send button. Nothing else is focusable in Phase 1 except sonner's toast close buttons.
- Every focusable element shows the 2px accent focus ring. Never `outline: none` without a replacement.
- All text meets 4.5:1 and non-text controls 3:1 against their background using the values above.
- Page `<html lang="en">`, page title `<h1>`, section headings `<h2>`, so heading levels do not skip.

### Presentation sizing

The demo is shown live. At a 1280px-wide viewport the single 720px column is acceptable. Do not add responsive breakpoints beyond the 480px wrap noted above.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Page title (h1) | SignalR Notification Demo |
| Primary CTA | Send broadcast |
| CTA while in flight | Sending… |
| Form heading | Send a broadcast |
| Input label | Message |
| Input placeholder | Say something to every open tab |
| Notifications heading | Notifications |
| Empty state heading | No notifications yet |
| Empty state body | Type a message above and choose Send broadcast. Open this page in a second tab to watch it arrive in both tabs. |
| Status labels | Connecting… / Connected / Reconnecting… / Disconnected |
| Status hint, server not up | Can't reach the server yet. Retrying every 2 seconds. |
| Status hint, reconnecting | Connection dropped. Trying to reconnect. |
| Status hint, disconnected | Connection lost. Reload the page to reconnect. |
| Error state (send failed) | Message not sent. The connection dropped. Wait for Connected, then try again. |
| Toast title | The kind label (Broadcast / User / Group / Task) |
| Toast body | The message text exactly as sent |
| Destructive confirmation | not applicable: Phase 1 has no destructive actions (no clear, delete or leave controls) |

Rules: sentence case everywhere; the ellipsis is the single character `…`; no exclamation marks; no emoji.

## UI Considerations

Applicable state considerations resolved: 14 covered, 1 backstop, 0 unresolved.

State copy for empty and error rows lives in the Copywriting Contract above; this table references it.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Notification list | ✅ covered | With zero entries the list renders the "No notifications yet" heading and empty-state body from the Copywriting Contract on a Secondary panel, not an empty `<ol>` |
| loading | Notification list | ✅ covered | The list has no fetch; it fills only from pushed events, so it has no loading state. Connection in-flight is covered by the Connecting status |
| error | Notification list | ✅ covered | No load can fail; connection failure is shown by the status pill and its hint, not inside the list |
| populated | Notification list | ✅ covered | Newest-first rows with kind badge, time and message, highlight on arrival, as specified in the list section |
| partial | Notification list | ✅ covered | A payload missing `kind` renders the neutral "Notification" badge; missing `message` renders an empty message line rather than throwing; missing `id` is not expected (server stamps it) |
| overflow | Notification list | ✅ covered | List capped at 50 entries, oldest dropped, page scrolls |
| zero-one-many | Notification list | ✅ covered | No count or plural copy is shown; layout is identical at one row and many rows |
| empty | Send form | ✅ covered | Empty or whitespace-only message keeps the Send button disabled; trimmed before send |
| loading | Send form, Send button | ✅ covered | In flight: button disabled and reads "Sending…"; input stays editable |
| error | Send form, Send button | ✅ covered | `invoke` rejection shows the inline send-error copy and keeps the typed text |
| partial | Send form | ✅ covered | Same as empty: whitespace-only counts as empty |
| long-text | Send form input, notification message, toast | ✅ covered | Input capped at 280 characters; list message uses `overflow-wrap: anywhere`; sonner wraps toast descriptions |
| error | Status pill | ✅ covered | Server unreachable, dropped, and lost each have a distinct status plus hint (Copywriting Contract) |
| loading | Status pill | ✅ covered | Connecting state with pulsing dot (static dot under reduced motion) |
| overflow | Page header at narrow width | 🧪 backstop | Title and pill wrap to two lines below 480px without horizontal scroll; confirm with a held-out viewport check |

Open-axis notes (real-time and accessibility, from the domain probe bank): arrival announcements rely on sonner's live region only (see Keyboard and accessibility). Out-of-order or duplicate delivery is handled by ignoring a repeated `id`. Notifications sent while this tab was disconnected are not shown later, by design (no catch-up buffer; README and Phase 5 script state it).
